# 插件使用频率统计功能 — 实施计划（v2 修订版）

## 已确认的需求口径

- **什么算一次"使用"**：NoneBot `run_preprocessor` 全局钩子捕获，handler 真正开始执行才计一次。权限被拒、未匹配上的不计。仅统计 `MessageEvent`（群聊/私聊）触发，notice/request 类不算。
- **粒度**：**明细记录** —— 每次使用插一行，记录插件、触发人、来源群、触发时间（v2 按用户要求从聚合计数改为明细表）。
- **排除名单**（.env 可追加）：默认排除插件自身、`logging_info`（on_message 全量监听）。
- **存储**：MySQL Bot DB（SQLAlchemy 2.0 async + asyncmy）。
- **环境隔离（v2 新增）**：开关 + 环境标签双保险，防止生产/测试共用数据库时数据混乱。
- **查看**：QQ 命令查询，MVP 文本榜单。

## 技术设计

### 1. 明细表 `plugin_usage_records`

新模型 `PluginUsageRecord` 放 `src/common/models/plugin_usage_models.py`（遵循 vv_models.py 独立模型文件惯例），风格对齐 botdb_models.py（`Mapped`/`mapped_column`、BigInteger 主键、naive 北京时间）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BigInteger PK | 自增 |
| module_name | String(255) | 插件模块名（如 `src.plugins.vv`），展示时映射中文名 |
| user_id | BigInteger | 触发用户 QQ 号 |
| group_id | BigInteger, nullable | 来源群号；私聊为 NULL |
| env_tag | String(20) | 环境标签，取 `ENVIRONMENT`（prod/local/dev/docker），隔离共用库的数据 |
| used_at | DateTime | 插件被触发的时间（`datetime.now()`，跟随项目时区惯例） |

索引：`Index(used_at)`、`Index(module_name, used_at)`、`Index(env_tag, used_at)`。

**展示名映射**：查询时经 `get_loaded_plugins()` 将 module_name 映射到 `PluginMetadata.name`（中文名，参考 `cmd_list/get_plugin_usage.py`）；已卸载插件 fallback 短名。

### 2. 采集钩子（新插件 `src/plugins/plugin_usage_stats/`）

```
src/plugins/plugin_usage_stats/
├── __init__.py    # PluginMetadata + run_preprocessor 钩子 + on_startup 幂等建表
├── config.py      # pydantic BaseModel via get_plugin_config()
├── dao.py         # 明细插入 + 榜单聚合查询 + 过期清理
├── scheduler.py   # 定期清理任务（nonebot_plugin_apscheduler）
└── commands.py    # 查询命令
```

`__init__.py` 全局钩子：

```python
@run_preprocessor
async def record_usage(matcher, bot, event, state):
    # 1. matcher.plugin 为 None（builtin echo 等）→ 跳过
    # 2. 非 MessageEvent → 跳过
    # 3. module_name 命中排除名单 → 跳过
    # 4. INSERT 明细（单条 insert，无竞态）；全程 try/except，统计失败只打日志、绝不影响消息流程
```

- 建表：插件自身 `on_startup` 执行 `Base.metadata.create_all`（幂等，不依赖权限系统钩子顺序）。

### 3. 环境隔离方案（v2 核心）

双保险，解决生产/测试共用 MySQL 的数据混乱：

1. **开关 `PLUGIN_USAGE_STATS_ENABLE`（默认 false，显式开启）**：false 时不注册钩子与命令。生产 `.env.prod` 设 true；测试环境（.env.local/.env.dev）不设或设 false，测试数据完全不落库。
2. **环境标签列 `env_tag`**：兜底。即使某环境误开，落库数据也带环境标记；查询命令**默认只统计当前环境**（`env_tag == 当前 ENVIRONMENT`）的数据，可传参数看全部。两环境同库同表互不污染。

### 4. 配置（config.py + env.template）

- `PLUGIN_USAGE_STATS_ENABLE`（默认 false）：总开关，各环境 .env.{ENVIRONMENT} 独立控制。
- `PLUGIN_USAGE_STATS_EXCLUDED`（默认 `"plugin_usage_stats,logging_info"`）：逗号分隔模块短名排除名单。
- `PLUGIN_USAGE_STATS_TOP_N`（默认 15）：榜单条数上限。
- `PLUGIN_USAGE_STATS_RETENTION_DAYS`（默认 365）：明细保留天数。
- 同步在 `env.template` 补充带注释条目（注明"生产/测试共库时，建议仅生产开启"）。

### 5. 查询命令

`on_command("插件统计", aliases={"usage", "pluginstat"})`，不挂权限系统（榜单为聚合数据，不暴露 user/group 明细，跟随 `help` 的无权限模式）。手写参数解析（项目风格）：

- `插件统计` → 本周 Top N（当前环境）
- `插件统计 今天|昨天|本周|本月|总` → 对应范围
- 可附加数字指定 Top N，如 `插件统计 本月 10`
- 输出文本榜单 `排名. 中文名（短名） 次数`，附统计周期与环境说明；无数据时提示。
- 明细已记录 user_id/group_id，未来可扩展"谁用得最多/哪个群最活跃"子命令（本次不做）。

### 6. 过期清理

`scheduler.py` 用 nonebot_plugin_apscheduler（项目已有依赖）每日 05:00 清理超过 `RETENTION_DAYS` 的明细行，防止明细表无限增长。

## 实施步骤

1. 新建 `src/common/models/plugin_usage_models.py`（PluginUsageRecord）。
2. 新建插件 `src/plugins/plugin_usage_stats/`：config.py → dao.py → scheduler.py → commands.py → `__init__.py`。
3. `env.template` 增加配置项说明。
4. 验证：启动确认建表无异常；测试群触发若干命令后 `插件统计 今天` 核对计数与 user/group/时间落库；确认 logging_info 不进榜、权限被拒命令不计数；验证开关关闭后完全不落库。

## 明确不做（本次范围外）

- 用户榜/群榜查询命令（数据已记录，命令后续可加）
- 命令级（Matcher 级）细分、WebUI 面板、定时播报、图片榜单渲染

## 风险备注

- `run_preprocessor` 触发在 permission 检查之后，handler 内部自查权限（如 `_ensure_superuser`）不拦截计数，属"真执行"口径，符合预期。
- 同一条消息触发多个 `block=False` matcher 各计一次，排除名单已覆盖主要污染源（logging_info）。
- 明细表每次使用一条 INSERT，消息量级下 MySQL 无压力；若未来量级暴涨可再加内存缓冲批量落库。
