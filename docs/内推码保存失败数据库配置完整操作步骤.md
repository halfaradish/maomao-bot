# 数据库配置与消息保存失败排查完整操作步骤

本文档用于解决机器人在保存消息时出现的数据库报错，例如：

```text
Access denied for user 'root'@'localhost' (using password: YES)
```

这类问题通常表示：机器人连接 MySQL 失败，或者数据库账号、密码、权限配置不正确。

---

## 一、问题现象

在运行机器人后，日志中出现类似内容：

```text
[ERROR] logging_info | 保存消息失败 (message_id=xxxxxx): (1045, "Access denied for user 'root'@'localhost' (using password: YES)")
```

这说明 `logging_info` 插件在保存消息时调用了数据库，但数据库认证失败了。

---

## 二、原因说明

本项目里的消息持久化功能通常通过 Django ORM 写入数据库。常见原因包括：

1. 数据库用户名或密码写错了
2. 使用了默认的 `root` 用户，但权限不足
3. 数据库服务没有启动
4. 数据库名不存在
5. `localhost` 连接方式不适配，应该改成 `127.0.0.1`
6. 项目配置和实际数据库环境不一致

---

## 三、推荐解决方案

建议不要直接使用 `root` 账号，而是专门创建一个用于机器人连接的数据库用户，例如：

- 数据库名：`botdb`
- 用户名：`maomao`
- 密码：自定义

这样更安全，也更容易排查问题。

---

## 四、完整操作步骤

### 步骤 1：确认 MySQL 服务已启动

先确保你的 MySQL 正在运行。

Windows 下可以在服务管理器中查看 MySQL 服务是否启动。

如果使用命令行，也可以先登录测试：

```bash
mysql -u root -p
```

如果这里都无法登录，先把 MySQL 本身修好。

---

### 步骤 2：创建数据库

登录 MySQL 后，创建一个专门给机器人用的数据库：

```sql
CREATE DATABASE botdb DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

如果数据库已经存在，可以跳过这一步。

---

### 步骤 3：创建专用用户

推荐新建一个非 root 用户：

```sql
CREATE USER 'maomao'@'localhost' IDENTIFIED BY 'ZZyyjj7203..';
```

如果机器人不是本机直连，而是容器、虚拟机、远程机器访问数据库，可以改成：

```sql
CREATE USER 'maomao'@'%' IDENTIFIED BY 'ZZyyjj7203..';
```

说明：
- `localhost` 表示只允许本机登录
- `%` 表示允许任意主机登录

---

### 步骤 4：给用户授权

把 `botdb` 的权限授权给这个用户：

```sql
GRANT ALL PRIVILEGES ON botdb.* TO 'maomao'@'localhost';
FLUSH PRIVILEGES;
```

如果前面创建的是 `%` 用户，就改成：

```sql
GRANT ALL PRIVILEGES ON botdb.* TO 'maomao'@'%';
FLUSH PRIVILEGES;
```

---

### 步骤 5：确认项目里数据库配置位置

在项目中搜索这些关键词，通常能找到 Django 的数据库配置：

- `DATABASES`
- `mysql`
- `root`
- `PASSWORD`
- `HOST`
- `botdb`
- `DB_`

常见位置包括：

- `settings.py`
- `config.py`
- `.env`
- `src/common/django_crud.py`
- Django 项目的配置文件

---

### 步骤 6：修改数据库连接配置

如果项目里是直接写死的数据库配置，建议改成下面这种形式：

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.mysql",
        "NAME": "botdb",
        "USER": "maomao",
        "PASSWORD": "你的密码",
        "HOST": "127.0.0.1",
        "PORT": "3306",
    }
}
```

这里建议注意两点：

1. `HOST` 尽量用 `127.0.0.1`，不要优先写 `localhost`
2. `USER` 不要继续用 `root`

---

### 步骤 7：如果项目使用 `.env`，就改环境变量

如果项目是通过环境变量读取数据库信息，可以写成：

```env
DB_ENGINE=django.db.backends.mysql
DB_NAME=botdb
DB_USER=maomao
DB_PASSWORD=你的密码
DB_HOST=127.0.0.1
DB_PORT=3306
```

然后在 Django 配置里读取：

```python
DATABASES = {
    "default": {
        "ENGINE": os.getenv("DB_ENGINE", "django.db.backends.sqlite3"),
        "NAME": os.getenv("DB_NAME", "db.sqlite3"),
        "USER": os.getenv("DB_USER", ""),
        "PASSWORD": os.getenv("DB_PASSWORD", ""),
        "HOST": os.getenv("DB_HOST", ""),
        "PORT": os.getenv("DB_PORT", ""),
    }
}
```

这样以后切换数据库更方便。

---

### 步骤 8：确认数据库驱动已安装

如果是 MySQL，Python 项目通常需要数据库驱动。

常见驱动有：

- `mysqlclient`
- `PyMySQL`

如果项目使用 `mysqlclient`，可以安装：

```bash
pip install mysqlclient
```

如果在 Windows 上安装困难，可以考虑使用 `PyMySQL`，但要确保项目代码和 Django 配置支持它。

---

### 步骤 9：执行迁移

数据库配置完成后，执行 Django 迁移，确保表结构存在：

```bash
python manage.py migrate
```

如果你的项目不是标准入口，就使用项目实际的启动方式。

迁移成功后，表会被创建或更新，消息保存功能才可以正常写入。

---

### 步骤 10：重启机器人并观察日志

修改完配置后，重启机器人。

如果一切正常，日志里不应再出现：

```text
Access denied for user 'root'@'localhost'
```

而是会看到消息保存成功相关日志。

---

## 五、推荐排查顺序

如果还是报错，建议按下面顺序检查：

1. MySQL 是否启动
2. 数据库 `botdb` 是否存在
3. 用户 `maomao` 是否创建成功
4. 用户是否拥有 `botdb` 的权限
5. 项目配置里是否还在使用 `root`
6. 密码是否正确
7. `HOST` 是否应该用 `127.0.0.1`
8. Django 驱动是否安装完整

---

## 六、快速验证数据库是否可用

你可以先用命令行测试登录：

```bash
mysql -u maomao -p -h 127.0.0.1 -P 3306
```

如果能正常进入 MySQL，说明账号和网络连接没有问题。

然后再检查数据库：

```sql
SHOW DATABASES;
USE botdb;
SHOW TABLES;
```

如果能正常查看数据库和表，说明数据库基础环境已经正常。

---

## 七、如果你只是想先让机器人跑起来

如果暂时不想配置 MySQL，也可以考虑临时使用 SQLite。

SQLite 配置示例：

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.sqlite3",
        "NAME": BASE_DIR / "db.sqlite3",
    }
}
```

适合：
- 本地调试
- 功能验证
- 不想马上部署 MySQL

不太适合：
- 高频写入
- 多进程并发
- 长期生产环境

---

## 八、常见错误说明

### 1. `Access denied for user 'root'@'localhost'`

说明：用户名、密码或权限错误。

解决：
- 不要用 root
- 改用新用户
- 检查授权

---

### 2. `Unknown database 'botdb'`

说明：数据库名不存在。

解决：
- 先执行 `CREATE DATABASE botdb ...`

---

### 3. `Can't connect to MySQL server`

说明：
- MySQL 没启动
- 端口不对
- 地址不对

解决：
- 检查 MySQL 服务
- 确认 `HOST` 和 `PORT`

---

### 4. `Table doesn't exist`

说明：
- 迁移没执行
- 表结构没生成

解决：
- 执行 `python manage.py migrate`

---

推荐你使用下面这套组合：

- 数据库名：`botdb`

## 十、总结

这个报错本质上不是消息逻辑的问题，而是数据库连接问题。

只要你完成以下三件事，通常就能解决：

1. 创建数据库
2. 创建专用用户并授权
3. 把项目里的数据库配置改正确

## 十一、重新安装 MySQL 后的完整配置步骤

下面这部分适用于你已经在 Windows 上重新下载并安装了 MySQL 的情况，按顺序执行即可。

### 步骤 1：启动 MySQL 服务

安装完成后，先确认 MySQL 服务已经启动。

在 PowerShell 中执行：

```powershell
sc query type= service state= all | findstr /i "mysql mariadb"
```

如果看到了类似 `MySQL80` 的服务名，启动它：

```powershell
net start MySQL80
```

如果你的服务名不同，就把 `MySQL80` 替换成实际名称。

---

### 步骤 2：登录 MySQL

常见安装路径下，`mysql.exe` 一般位于：

```text
C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe
```

如果你的版本不同，请按实际安装目录替换。

使用完整路径登录：

```powershell
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p
```

输入 root 密码后，如果进入 `mysql>` 提示符，说明连接成功。

---

### 步骤 3：创建机器人数据库与用户

进入 MySQL 后执行：

```sql
CREATE DATABASE botdb DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'maomao'@'localhost' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON botdb.* TO 'maomao'@'localhost';
FLUSH PRIVILEGES;
```

如果你的项目未来会从其他主机或容器访问数据库，可以把用户名主机改成 `%`：

```sql
CREATE USER 'maomao'@'%' IDENTIFIED BY '你的密码';
GRANT ALL PRIVILEGES ON botdb.* TO 'maomao'@'%';
FLUSH PRIVILEGES;
```

---

### 步骤 4：在项目中修改数据库配置

把项目里的数据库配置改成：

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.mysql",
        "NAME": "botdb",
        "USER": "maomao",
        "PASSWORD": "你的密码",
        "HOST": "127.0.0.1",
        "PORT": "3306",
    }
}
```

注意：

- 不要再使用 `root`
- `HOST` 建议使用 `127.0.0.1`
- `PORT` 如果 MySQL 默认安装，一般就是 `3306`

---

### 步骤 5：如果项目使用环境变量

如果你的项目通过 `.env` 配置数据库，可以写成：

```env
DB_ENGINE=django.db.backends.mysql
DB_NAME=botdb
DB_USER=maomao
DB_PASSWORD=你的密码
DB_HOST=127.0.0.1
DB_PORT=3306
```

对应的 Django 配置示例：

```python
DATABASES = {
    "default": {
        "ENGINE": os.getenv("DB_ENGINE", "django.db.backends.sqlite3"),
        "NAME": os.getenv("DB_NAME", "db.sqlite3"),
        "USER": os.getenv("DB_USER", ""),
        "PASSWORD": os.getenv("DB_PASSWORD", ""),
        "HOST": os.getenv("DB_HOST", ""),
        "PORT": os.getenv("DB_PORT", ""),
    }
}
```

---

### 步骤 6：安装数据库驱动

确保 Python 已安装 MySQL 驱动：

```bash
pip install mysqlclient
```

如果 Windows 编译失败，可以考虑使用 `PyMySQL`，但要保证项目代码兼容。

---

### 步骤 7：执行迁移

在项目根目录执行：

```bash
python manage.py migrate
```

这一步会创建或更新数据库表，确保消息保存功能能正常写入。

---

### 步骤 8：验证连接

先在命令行测试新用户是否能登录：

```powershell
"C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u maomao -p -h 127.0.0.1 -P 3306
```

如果可以顺利登录，再查看数据库：

```sql
SHOW DATABASES;
USE botdb;
SHOW TABLES;
```

---

### 步骤 9：重启机器人并查看日志

完成以上步骤后，重启机器人。若配置正确，日志里不应再出现：

```text
Access denied for user 'root'@'localhost'
```

而应能正常保存消息。

---

## 十二、最终建议

如果你刚重新安装 MySQL，最稳妥的流程是：

1. 启动 MySQL 服务
2. 用 root 登录一次
3. 创建 `botdb` 数据库
4. 创建 `maomao` 用户并授权
5. 把项目配置改到 `maomao` 用户
6. 安装驱动并执行迁移
7. 重启机器人验证

这样就能把“保存消息失败”的问题彻底解决。
