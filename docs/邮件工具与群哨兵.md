# 公共邮件工具与群哨兵接入

`src/common/email_sender.py` 是普通 Python 公共模块，不是新的 NoneBot 插件。
它提供 `send_email()`，群哨兵及其他业务插件都可以调用。群哨兵在初审未通过、
申请挂起等待人工复核时，向申请人的 `QQ号@qq.com` 发送说明；不自动拒绝申请，
也不把邮件发送成功当作审核完成。初审通过仍按原逻辑自动批准，不发送待复核邮件。

代码分工：`email_sender.py` 负责邮件格式和 SMTP，`email_delivery.py` 负责记录、
去重、限流和安全重试；群哨兵负责待复核说明及申请标识。它们不是两个新插件。

## 配置与开启

默认不发真实邮件。确认当前进程实际使用的环境文件，在里面配置：

```dotenv
EMAIL_ENABLED=true
EMAIL_DRY_RUN=true
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURITY=ssl
SMTP_USERNAME=你的发件QQ号@qq.com
SMTP_PASSWORD=你的邮箱SMTP授权码
SMTP_FROM_NAME=谛听机器人

GROUP_SENTINEL_EMAIL_ENABLED=true
GROUP_SENTINEL_EMAIL_HTML=true
GROUP_SENTINEL_EMAIL_SUBJECT=入群申请待人工复核
GROUP_SENTINEL_EMAIL_CONTACT=群主 QQ：1950482412
```

`EMAIL_DRY_RUN=true` 会校验并构建邮件，但不会连接邮箱服务器，也不占用真实发送
记录和限流额度。群哨兵先发送群内待人工复核通知，再用一条简短消息说明邮件状态
（包括模拟发送）；邮件功能关闭时只发送原有待复核通知。确认配置后把模拟开关设为 `false`，
重新加载 Bot 配置才会真实发送。
模拟模式下 QQ 的审核仍真实运行：通过则批准，未通过则保持申请待人工复核；仅邮件不发。

群哨兵本身仍需启用 `GROUP_SENTINEL_ENABLED`，并符合原有群权限规则；本次不改
学号校验和权限判断，沿用上游“初审未通过则挂起”的行为。申请人不一定已开通 QQ 邮箱，SMTP 接收邮件
也不等于实际投递成功；服务商后续退信需要在发件邮箱查看。

项目在 `bot.py` 中先加载 `.env`，再按 `ENVIRONMENT` 加载 `.env.prod` / `.env.dev`；
新版未设置 `ENVIRONMENT` 时默认 `dev`。目前没有使用
`override=True`。**已经存在的环境变量以及 `.env` 中同名值不会被后一个文件覆盖**。
因此请在同一个生效位置配置邮件变量，避免 `.env` 中的 `false` 覆盖你在
`.env.prod` 中填写的 `true`。授权码仅保存在部署环境，不写入代码或 Git。

完整变量见根目录 `env.template`。其他可选项：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `SMTP_FROM_EMAIL` | `SMTP_USERNAME` | 发件地址，须为服务商允许的地址 |
| `SMTP_SECURITY` | `ssl` | `ssl` 或 `starttls`，始终验证服务器证书 |
| `SMTP_PORT` | `ssl` 为 465，`starttls` 为 587 | 显式填写时优先使用指定端口 |
| `SMTP_TIMEOUT` | 10 | 每次 socket 操作的超时秒数 |
| `EMAIL_MAX_MESSAGE_BYTES` | 20971520 | 编码后邮件大小上限，包含附件 |
| `EMAIL_RECORD_DB` | `data/email_delivery.sqlite3` | 发送记录与去重数据库 |
| `EMAIL_WORKERS` | 2 | 单进程邮件专用线程数，修改后重启 |
| `EMAIL_QUEUE_SIZE` | 20 | 单进程等待队列容量，修改后重启 |
| `EMAIL_RATE_COUNT` / `EMAIL_RATE_WINDOW` | 30 / 60 | 同一记录库每 60 秒最多 30 次 SMTP 尝试 |
| `EMAIL_RECIPIENT_RATE_COUNT` / `EMAIL_RECIPIENT_RATE_WINDOW` | 3 / 3600 | 同一收件人或业务限流标识每小时最多 3 次尝试 |
| `EMAIL_RETRY_ATTEMPTS` | 3 | 总尝试次数（含首次），最多可设为 5 |
| `EMAIL_RETRY_DELAY` | 1 | 首次重试等待秒数，后续指数退避 |
| `GROUP_SENTINEL_EMAIL_HTML` | `false` | 同时发送纯文本和 HTML 待人工复核说明 |

切换 STARTTLS 时，若从模板复制了 `SMTP_PORT=465`，请一起改成服务商要求的端口。
不支持 STARTTLS 时不会回退到明文认证。未配置完整 SMTP 时，邮件返回配置错误，
申请仍保持待人工复核状态，不会因为邮件失败而自动拒绝或批准。

从旧的拒绝邮件版本升级时，若自己的 `.env` 已设置
`GROUP_SENTINEL_EMAIL_SUBJECT=入群申请审核未通过`，请改成 `入群申请待人工复核`，
因为显式环境配置优先于代码默认值。联系人配置和 SMTP 凭据不需要因为这次文案变化而更换。
通知正文明确说明“不是最终拒绝，无需重复提交申请”，不再要求申请人重新申请。

启用 `GROUP_SENTINEL_EMAIL_HTML=true` 后，待复核通知使用浅色卡片排版：状态标签、
群号及初审原因信息区、后续操作说明、可选联系人区。采用自适应宽度的表格和内联样式，
不加载外部图片、字体或脚本；联系人留空时不显示联系人卡片。纯文字备用正文仍然保留。
不同邮箱的圆角、颜色等显示可能略有差异，正式使用前仍需在实际收件邮箱查看效果。

## 在其他插件中使用

在正常启动的 NoneBot 中直接导入，不需要 `require()`：

```python
from src.common.email_sender import send_email, EmailSendError

try:
    result = await send_email(
        to="123456789@qq.com",
        subject="处理结果",
        text="您好，您的申请已经处理。",
        idempotency_key="业务名:本次通知的唯一编号",
        rate_limit_key="user:本次用户编号",  # 可选，收件地址本身也受限流保护
    )
except EmailSendError as exc:
    # unknown 不能盲目补发。record_id 可用于定位发送记录。
    logger.warning(f"邮件状态: {exc.delivery_state}, 错误: {exc.code}, 记录: {exc.record_id}")
else:
    logger.info(f"邮件状态: {result.status}")
```

工具在调用时读取环境变量，也允许传入 `config=SMTPConfig(...)` 使用独立配置。
`src.common` 已改成按需导入；普通独立脚本也可以直接导入邮件工具，无须先初始化
NoneBot、数据库或 Redis。独立脚本需要自行设置环境变量或传入 SMTPConfig，工具
不会自动读取 `.env`。记录、限流等调度参数统一读取当前进程环境变量。

HTML、多收件人、抄送、密送、回复地址和附件示例：

```python
from html import escape
from src.common.email_sender import EmailAttachment, send_email

display_name = escape(user_display_name)  # 插入用户数据前转义
result = await send_email(
    to=["student@example.com", "teacher@example.com"],
    cc="copy@example.com",
    bcc="archive@example.com",
    reply_to="support@example.com",
    subject="处理结果",
    text=f"您好，{user_display_name}，您的申请已经处理。",
    html=f"<h2>处理结果</h2><p>您好，{display_name}，您的申请已经处理。</p>",
    attachments=[
        EmailAttachment(
            filename="说明.txt",
            data="联系管理员了解详情。".encode("utf-8"),
            content_type="text/plain",
        ),
    ],
)
```

`text` 和 `html` 至少提供一个；同时提供时自动生成 `multipart/alternative`，
客户端可选择适合显示的版本。HTML 由调用方生成，公共工具不会执行模板、转义正文
或自动把 HTML 转换成纯文本。群哨兵自己的 HTML 模板会转义变量，并提供对应纯文本。

每个地址参数接收单个裸邮箱地址或地址列表，多个地址应使用列表，不能放在一个
逗号分隔的字符串中。支持 UTF-8 正文、主题、显示名、附件名以及国际化域名；暂不
支持非 ASCII 邮箱本地部分。密送只进入 SMTP 信封，不出现在邮件头。
附件接收字节数据，不读取用户传入的磁盘路径。正文内嵌图片可用 CID：

```python
result = await send_email(
    to="student@example.com",
    subject="图文通知",
    text="请查看图文通知。",
    html='<p>处理结果</p><img src="cid:logo" alt="标志">',
    attachments=[EmailAttachment("logo.png", png_bytes, "image/png", content_id="logo")],
    idempotency_key="图文通知:唯一编号",
)
```

`png_bytes` 是调用方读取的图片字节。`content_id` 不含尖括号，邮件内须唯一，只
允许 `image/*`，并且必须提供 HTML 正文；普通附件不设置 `content_id` 即可。

## 结果、错误和防重复

| `result.status` | 含义 |
| --- | --- |
| `sent` | SMTP 接受所有收件人，不保证最终到达收件箱 |
| `partial` | 部分收件人被拒绝，查看 `accepted` / `refused` 地址元组 |
| `disabled` | 全局工具关闭，没有发送 |
| `dry_run` | 只校验和构建，没有发送 |
| `duplicate` | 相同标识已有 `sent` 或 `partial` 记录，本次未重复发送 |

`message_id` 为所构建邮件的 ID；`disabled` 时为空。`record_id` 是本地记录 ID，
`refused_codes` 提供部分拒收地址对应的数字响应码，不保留服务器原始文本。
所有收件人均被拒绝、
认证失败、配置错误或网络异常会抛出 `EmailSendError`。错误分类包括
`configuration`、`message`、`authentication`、`recipients_refused`、`tls`、
`timeout`、`connection`、`smtp`、`internal`，以及调度层的 `busy`（队列满）、
`rate_limited`（限流）、`storage`（记录库不可用）、`key_conflict`（标识收件人冲突）、
`in_progress` / `uncertain`（已有未确认的发送记录）。

自动重试必须同时满足：`delivery_state == "not_sent"`、`retryable == True`，且未
超过尝试次数和限流额度。提交前的临时网络失败、明确的 SMTP 临时拒绝可能重试；
配置错误、认证错误和永久拒收不会自动重试。修好这类错误后，调用方可以携带原标识
再次调用，不再像旧版本一样锁定 7 天。

一旦进入提交阶段，断连或超时可能发生在服务端已经接收之后，记录为 `unknown`，
禁止自动重试和相同标识再次发送。多个收件人部分失败时也不会整封重发，避免重复
投递给已接受的收件人。`sent` 只说明 SMTP 接受，不等于对方已收到或阅读。

群哨兵用 `group_sentinel:pending_review:` 前缀加 Bot ID、群号、请求 `flag` 组成幂等标识；只在记录库中保存其摘要，
不保存原始 `flag`。不同请求标识的同一 QQ 用户仍受每人限流约束。公共工具其他
调用方也应传入稳定的 `idempotency_key`；不传时只记录和限流，不跨调用去重。

阻塞的 MIME/SMTP/SQLite 操作在邮件专用有界线程池执行，不占用默认线程池。
调用协程取消后，已入队工作仍继续执行并写回结果，不会提前释放容量；取消不是撤销
发送。`SMTP_TIMEOUT` 是每次网络操作的超时，不是包含排队和重试的总时限。

## 发送记录在哪里，怎么查询

默认文件：`data/email_delivery.sqlite3`，相对路径以进程工作目录为准。Docker 中若
工作目录为 `/app`，就是 `/app/data/email_delivery.sqlite3`，通过已有的 `/app/data`
挂载保存在宿主机；不修改原业务 MySQL，也不需要 MySQL 建表迁移。

记录库保存收件邮箱（**包括密送地址，应限制访问**）、发送时间、状态、尝试次数、
Message-ID、接受/拒收结果和脱敏错误码；不保存正文、附件、主题或授权码。禁用、
模拟、调度参数无效、队列满、预校验失败时可能没有记录，因为尚未进入真实投递处理。

在项目根目录只读查看最近记录：

```bash
python -m src.common.email_delivery --limit 20
python -m src.common.email_delivery --recipient 123456789@qq.com --status not_sent
```

服务器容器内查看：

```bash
sudo docker exec -w /app diting-nonebot python -m src.common.email_delivery --db /app/data/email_delivery.sqlite3 --limit 20
```

查询命令不会自动加载 `.env`，自定义路径时用 `--db` 明确指定。查询不创建数据库，
还没发生真实投递处理时提示文件不存在属于正常现象。也可在代码中使用只读接口
`from src.common.email_delivery import list_email_records`。`email_deliveries` 是每个通知
的最新状态，`email_attempts` 保存历次尝试明细；时间为 Unix 时间戳。

### 使用边界

- 同一 SQLite 文件内可跨进程原子去重和限流；不同文件、不同服务器之间不共享。
  生产和测试各自挂载的 `data` 目录应保留隔离，不能把同库承诺理解成全服务器同步。
- SQLite 应放在本机持久化磁盘，不放网络文件系统。没有记录库访问权限或磁盘满时
  停止本次发信，不会绕过记录保护。两个进程共享记录库时应采用一致的限流参数。
- `sending` 可能表示正在处理，也可能是进程崩溃留下的记录；不会擅自清除或补发。
  `unknown` / 长期 `sending` 需要核查发件邮箱、Message-ID 等证据并人工联系申请人。
- **这不是持久化任务队列**：排队中的正文只在内存，重启不自动恢复任务；没有定时
  补发服务。重试次数用尽、限流、队列满后，群内会提示，需要调用方后续明确重试或
  人工处理。旧的待复核申请不保证会再次推送，因此修配置不会自动补发旧申请。
- 默认保留发送记录，不自动删除已发标识。备份时保护收件人隐私；不要直接删除
  整个记录库来处理故障，否则去重历史也会丢失。长期高量场景再扩展归档和任务队列。
- SMTP 不支持严格“恰好一次”，也无法凭 SMTP 提交结果确认收件箱送达。退信查看、
  定时群发、模板管理和 OAuth 等不在此次范围内。

## 离线验证

在项目根目录运行：

```bash
python -m unittest discover -s src/common/tests -v
```

测试使用模拟 SMTP 和模拟 QQ 事件，不发送邮件、不批准或拒绝真实申请，也不连接
数据库/Redis。正式投递还需在部署环境配置账号后进行受控联调。

实现依据：[Python smtplib 文档](https://docs.python.org/3/library/smtplib.html)、
[Python email MIME 示例](https://docs.python.org/3/library/email.examples.html)。
